# Admin Dashboard Implementation Plan

## Overview

Extend EcoMart e-commerce platform with a role-based admin dashboard featuring:
- **Super Admin**: Full control over all vendors, products, orders, and system settings
- **Vendors**: Manage their own products and orders

## Phase 1: Backend - Role-Based Access Control

### 1.1 Update User Model (`server/src/models/User.ts`)
- Add `role` field: `customer`, `vendor`, `super-admin`
- Add `vendorId` field (for tracking which vendor created a product/order)
- Add vendor profile fields: `storeName`, `storeDescription`, `isActive`

### 1.2 Update Auth Middleware (`server/src/middleware/auth.ts`)
- Add `role` to JWT payload
- Create `requireRole(...roles)` middleware for role-based access control
- Create separate `requireVendor` and `requireSuperAdmin` middlewares

### 1.3 Create Vendor Model (NEW)
- Fields: `name`, `email`, `phone`, `address`, `logo`, `banner`, `description`, `isActive`, `createdBy` (super-admin who created)

### 1.4 Update Product Model (`server/src/models/Product.ts`)
- Add `vendorId` field to track product ownership
- Add `isApproved` boolean field for super-admin approval

### 1.5 Update Order Model (`server/src/models/Order.ts`)
- Add optional `vendorId` field to track which vendor fulfilled each item

## Phase 2: Backend - Admin API Routes

### 2.1 Create Admin Routes (`server/src/routes/admin.ts`)
- Vendor management: CRUD for vendors (super-admin only)
- Product management: Get all products, approve/reject products (super-admin), vendor products management
- Order management: Get all orders, update order status (super-admin/vendor based on ownership)
- Analytics: Sales stats, revenue, product counts (super-admin only)

### 2.2 Update Existing Routes
- Products: Add vendor-specific endpoints and approval checks
- Orders: Add vendor access to their orders

### 2.3 Add Admin Registration/Login
- Vendor registration endpoint (requires super-admin approval)
- Vendor login with role-based token generation

## Phase 3: Frontend - Admin Dashboard

### 3.1 Create Admin Directory Structure
```
client/src/admin/
  pages/
    - Dashboard.tsx (overview/stats)
    - ProductsPage.tsx (product management)
    - OrdersPage.tsx (order management)
    - VendorsPage.tsx (super-admin only)
    - LoginPage.tsx
  components/
    - AdminLayout.tsx
    - AdminSidebar.tsx
    - StatsCard.tsx
    - ProductTable.tsx
    - OrderTable.tsx
    - VendorTable.tsx
  context/
    - AdminAuthContext.tsx
```

### 3.2 Admin API Endpoints (`client/src/api/admin.ts`)
- `adminAPI.login()`, `adminAPI.getMe()`
- `productsAPI.admin.getAll()`, `update()`, `delete()`, `approve()`
- `ordersAPI.admin.getAll()`, `updateStatus()`
- `vendorsAPI.getAll()`, `create()`, `update()`, `delete()`

### 3.3 Routing (`client/src/App.tsx`)
- Add `/admin/*` routes with AdminLayout wrapper
- Protected routes using AdminAuthContext

## Phase 4: Features by Role

### Super Admin Features
- Dashboard with analytics (total sales, orders, vendors, products)
- Vendor management (view, create, edit, deactivate)
- Product oversight (view all, approve/reject)
- Order oversight (view all orders, update any status)
- User management (view all users)

### Vendor Features
- Dashboard with vendor stats (own sales, orders, products)
- Product CRUD (create, read, update, delete own products)
- Order management (view/process own orders only)
- Profile management

## Phase 5: Deployment

- Admin routes at `/admin/*` on the same Vercel deployment
- Update CORS to include admin paths on the-ecomart.vercel.app
- Add admin URL to environment configuration

## Estimated Implementation Order

1. Backend models (User, Vendor)
2. Backend middleware and role checks
3. Backend admin routes
4. Admin API client functions
5. Admin login page
6. Admin dashboard pages
7. Frontend routing integration
8. Testing and deployment

## Dependencies to Consider

- No additional backend dependencies needed (using existing express/mongoose)
- No additional frontend dependencies needed (using existing React/Tailwind)

## Security Considerations

- Separate JWT tokens or role-based access in existing tokens
- Rate limiting on admin endpoints
- Input validation for all admin actions
- Audit logging for sensitive operations
